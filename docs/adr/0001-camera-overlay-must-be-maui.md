# 悬浮在相机预览上的控件必须与相机同处一个原生视图树

扫描页的相机预览是原生 MAUI 视图，绘制在整个跨平台 UI 表面之上；因此用跨平台 UI 的层叠顺序（ZIndex 等）**无法**让控件盖住相机画面——实测中按钮会被相机画面完全遮住。要让控件悬浮在预览之上，唯一可行方式是把控件放进承载相机的同一个原生视图容器中，并按子元素添加顺序决定前后（相机在先、控件在后）。

## Considered Options

三条路线在仓库的并行分支中被实际实现并对比过：

- **跨平台 UI 叠加**：控件与相机放在跨平台 UI 的同一网格单元内，靠层叠顺序压住。**不可行**——原生相机视图永远绘制在其上层，控件被完全遮挡。
- **MAUI 视图叠加**（采用）：控件与相机同处原生容器的视图树内，相机在前、控件在后添加。已验证可点击、可显示。
- **Android 原生视图叠加**：直接创建平台原生控件并加入原生视图树。可行，但需要平台特有代码与宿主抽象，复杂度更高。

## Consequences

- 悬浮控件只在注册了原生相机宿主的平台上渲染；当前只有 Android 端这样做，桌面端不会出现这些控件。桌面端若需要同等能力，需另行设计（目前未决）。
- 悬浮控件用不上跨平台 UI 的数据绑定，只能代码接线：点击回调直接调用视图模型的操作，或经视图模型事件桥接到相机控件。
- 相机内容不可拆卸后重新挂载（相机会话不会自动重建，预览会永久空白），因此承载相机的容器及其内容必须幂等地构建并复用。
- 未来若有人想用普通 UI 叠加实现同类效果，应先读到本记录，而不必重新踩一遍坑。
