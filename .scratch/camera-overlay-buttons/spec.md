# Spec：相机预览右上角悬浮按钮组

Status: ready-for-agent

## Problem Statement

用户在扫描页操作闪光灯（Torch）与切换摄像头（Camera）时，必须把手指从屏幕上半部的取景区域挪到底部命令栏。底部命令栏在相机预览图层**之外**（位于其下方的独立行），因此：

- 单手竖持手机时，底部三个按钮在远端，拇指需要大幅下移，成像构图容易被打断；
- 取景时视线停留在画面上部，底部按钮不在视野焦点内，用户需要来回扫视；
- 相机预览本身是全宽的大面积实时画面，而命令栏独占一行高度，压缩了取景区域。

用户希望在不放弃底部命令栏的前提下，能在取景画面的右上角直接触达同样的三个操作。

## Solution

在相机预览图层的右上角叠加一组与其功能相同的三个按钮（Torch / Cancel / Camera），水平排成一行、右对齐，紧凑尺寸，垫深色半透明底板以保证在相机亮画面上的可读性。底部命令栏原样保留，两组按钮触发同一套相机操作；用户可任选一处操作。

该悬浮按钮组必须与相机画面处于同一个原生视图树中（这是本仓库已验证的唯一可行叠加方式，见 `docs/adr/0001-camera-overlay-must-be-maui.md`），因此它只在 Android 上渲染；桌面端维持现状（只有底部命令栏，无悬浮按钮组）。

## User Stories

1. 作为使用扫描功能的手机用户，我希望在相机预览的右上角看到 Torch、Cancel、Camera 三个按钮，这样我不必把手指移到屏幕底部就能操作它们。
2. 作为使用扫描功能的手机用户，我希望这三个按钮水平排成一行并贴着预览区域的右上角右对齐，这样它们的位置符合我对"窗口控件在右上角"的既有预期，不用重新学习。
3. 作为使用扫描功能的手机用户，我希望悬浮按钮真的显示在实时相机画面**之上**（而不是被相机画面遮住、或挤在画面旁边），这样它们才是"悬浮"在预览上而不是另占一行。
4. 作为使用扫描功能的手机用户，我希望悬浮按钮采用比底部按钮更紧凑的尺寸，这样它们不会在窄屏上横向溢出，也不会大面积遮挡取景。
5. 作为使用扫描功能的手机用户，我希望悬浮按钮下面垫一层深色半透明底板，这样在相机取景到明亮场景（天空、白墙、雪地）时按钮文字与边界依然清晰可辨。
6. 作为使用扫描功能的手机用户，我希望悬浮按钮的文案与配色沿用底部按钮（Khaki 黄底 Torch / Bisque 橙底 Cancel / AliceBlue 蓝底 Camera），这样两组按钮的对应关系一眼可辨。
7. 作为使用扫描功能的手机用户，我希望悬浮按钮组只占据右上角一小块区域，这样画面中心与条码可能出现的区域保持无遮挡。
8. 作为使用扫描功能的手机用户，我希望点悬浮的 Torch 按钮与点底部的 Torch 按钮效果完全相同（开关闪光灯），这样两处入口可以互相替代。
9. 作为使用扫描功能的手机用户，我希望点悬浮的 Camera 按钮与点底部的 Camera 按钮效果完全相同（切换前后摄像头），这样两处入口可以互相替代。
10. 作为使用扫描功能的手机用户，我希望点悬浮的 Cancel 按钮与点底部的 Cancel 按钮效果完全相同（关闭扫描页回到主页），这样两处入口可以互相替代。
11. 作为使用扫描功能的手机用户，我希望悬浮按钮的点击有即时的按下反馈，这样我知道自己的触碰被接收了。
12. 作为使用扫描功能的手机用户，我希望悬浮按钮在相机开始取景后立即出现（不需要额外点击或等待），这样进入扫描页的体验不被打断。
13. 作为使用扫描功能的手机用户，我希望底部命令栏仍然保留可用，这样在需要时可以按我既有的习惯操作，不会因为新功能而丢失原有入口。
14. 作为使用扫描功能的手机用户，我希望反复进入/退出扫描页时右上角始终只有一组悬浮按钮（不叠加出两组、三组），这样界面不会随着使用次数变得越来越乱。
15. 作为使用扫描功能的手机用户，我希望扫码成功跳到结果页时，右上角悬浮按钮不会盖在结果内容之上干扰阅读。
16. 作为使用扫描功能的手机用户，我希望从结果页点 "Scan Again" 回到取景时，右上角悬浮按钮重新可见，这样我可以立刻继续操作。
17. 作为使用扫描功能的手机用户，我希望全过程中相机预览保持实时流畅（悬浮按钮的出现不导致相机会话重启或预览变空白），这样扫描能力不被新功能破坏。
18. 作为使用扫描功能的手机用户，我希望闪光灯已开启时再次点悬浮 Torch 能把它关掉（开关语义与底部一致），这样两处入口的行为语义完全等价。
19. 作为使用扫描功能的手机用户，我希望前后摄像头切换后取景立即切到新摄像头，这样切换是我能立刻看到结果的操作。
20. 作为使用扫描功能的手机用户，我希望悬浮按钮的底板不过度遮挡——只在按钮背后一小条区域,而不是横跨整个画面顶部，这样取景区域损失最小。
21. 作为在桌面端运行的开发者，我希望桌面端不显示这组悬浮按钮（因为桌面没有相机原生宿主），同时不因此崩溃或报错，这样跨平台构建仍然可用。
22. 作为维护这段代码的开发者，我希望原本用于验证机制的品红 SPIKE 探针按钮被彻底移除（包括其点击切换颜色与弹 Toast 的测试行为），这样产品界面里不再出现测试残留。
23. 作为维护这段代码的开发者，我希望与相机层级相关的诊断日志只在需要时输出，不再因为探针按钮而持续打印无用信息。
24. 作为维护这段代码的开发者，我希望"悬浮在相机预览上的控件必须与相机处于同一个原生视图树"这条约束被记录为 ADR，这样未来有人再尝试用普通 UI 叠加方式实现同样效果时，能先读到"这条路已验证走不通"而不必重新踩一遍坑。
25. 作为维护这段代码的开发者，我希望下次要在预览上加控件时，能直接复用本次建立的按钮构建与摆放约定（右上、水平、紧凑、带底板），这样同类需求不需要重新摸索。
26. 作为维护这段代码的开发者，我希望术语表里明确"相机预览"指的是实时相机画面（而非拍照后的静态图），"悬浮按钮"指的是叠加在预览之上、与相机同处一个原生视图树的控件，这样后续讨论与文档不会在这两个词上产生歧义。
27. 作为使用扫描功能的手机用户，我希望这组新按钮不会改变扫描本身的任何行为（识别速度、识别率、扫码成功后跳转），这样新功能是纯增量的。

## Implementation Decisions

**功能定位**：纯增量 UI 叠加。不新增任何扫描/相机业务逻辑，三个悬浮按钮是对已有三个操作的第二个入口。

**改动的模块**：

- **扫描视图（ScannerView，code-behind）**：唯一的实质改动点。相机内容本身就是在代码中构建的（当前该构建逻辑仍是带品红探针按钮的 SPIKE 形态）。将探针按钮替换为一个右上角悬浮按钮面板，加入与相机同一个原生视图容器，并保持原有的幂等缓存语义（重复进入扫描页时复用已构建的相机与内容，不重建、不重复添加子元素）。
- **扫描视图模型（ScannerViewModel）**：不改。三个操作（Torch 开关、Camera 前后切换、Cancel 关闭扫描页）已存在，悬浮按钮直接复用。Torch 与 Camera 沿用既有的事件桥接路径（视图模型发事件、视图层落到相机控件），Cancel 直接作用于主页面的扫描页可见性。
- **扫描视图布局（XAML）**：底部命令栏原样保留、不做改动（本次不移除、不迁移）。顶层网格仍是"相机行 + 命令栏行"两行结构。
- **验证文档（`docs/maui-overlay-verification.md`）**：补充本次右上角按钮的手动验证步骤与结果。
- **新增 ADR（`docs/adr/0001-camera-overlay-must-be-maui.md`）**：记录核心架构约束与取舍背景。
- **新增术语表（`CONTEXT.md`）**：记录本次确立的两个术语及其 `_Avoid_` 同义词。

**叠加机制（关键约束）**：悬浮控件必须与相机处于**同一个原生视图树**中，并按子元素添加顺序决定前后关系（相机在下、按钮面板在上）。使用普通 UI 框架的层叠顺序（ZIndex 等）**无法**让控件盖住相机画面——相机是原生视图，绘制在整个 UI 表面上层。这条约束已由本仓库既有验证确认（见 `docs/maui-overlay-verification.md`），也是另一个并行分支对比 Avalonia / MAUI / Native 三种叠加方案后得出的结论。

**按钮组的布局约定**：

- 位置：相机预览图层的右上角（水平靠右、垂直靠上）。
- 排列：水平一行三个。
- 尺寸：紧凑版，明显小于底部命令栏按钮（底部为 100 单位宽）。
- 底板：深色半透明（`#80000000` 量级），只覆盖按钮背后一条，不横跨整个画面宽度。
- 文案与配色：沿用底部三个按钮的文案与三组颜色对（Khaki 黄 / Bisque 橙 / AliceBlue 蓝）。

**交互约定**：

- 三个悬浮按钮的点击直接调用扫描视图模型的三个既有操作，与底部按钮走同一路径、产生同一效果。
- 两组按钮是"独立副本"：各自独立触发。注意相机只有**一个**手电与**一个**摄像头位置，因此底层状态天然共享；"独立"仅体现为两处互不感知对方的按下反馈。本次**不**为按钮增加激活态/开关态的视觉同步（底部按钮当前也没有该视觉），即不引入"哪一处是开关真实状态"的新概念。
- 按钮的出现与消失完全由扫描页自身的可见性决定：进入扫描页即出现，进入结果页时被结果覆盖层自然遮挡，点 "Scan Again" 返回取景即恢复。**不**实现额外的自动隐藏逻辑。

**健壮性**：

- 保持现有的幂等行为：重复进入扫描页不得重复构建或重复添加按钮组。
- 相机内容不可拆卸重挂（既有约束），本次改动不得引入任何"移除并重新挂载相机"的行为，否则预览会永久空白。

**平台**：

- 悬浮按钮组只在 Android 上渲染（该平台注册了原生相机宿主）。桌面端不注册原生宿主，因此这组按钮在桌面不出现；桌面端保持只有底部命令栏的现状，本次不做桌面端方案。

## Testing Decisions

**决策：本次不新增自动化测试接缝，采用 Android 模拟器手动验证。**

理由：

- 本仓库目前**没有任何自动化测试工程或测试基础设施**，既有验证方式只有模拟器手动验证（`docs/maui-overlay-verification.md` 记录了像素级截图证据）。
- 本次功能不新增任何业务逻辑：三个按钮复用扫描视图模型上已存在的三个操作，接线极薄。为 3 个按钮新建一个测试工程（且需要在无原生应用上下文的环境中实例化原生控件）成本远高于收益。
- 符合"优先沿用既有接缝、新接缝越少越好"的原则。

**什么算好测试（本次遵循的外部行为视角）**：只断言用户能观察到的行为，不断言实现细节——不断言"按钮由哪个类构造""在视图树中的下标是多少"，只断言"右上角出现了三个可点的按钮""点击分别产生闪光灯开关、摄像头切换、关闭扫描页这三个可观察结果"。

**验证范围与步骤（在 Android 模拟器上执行）**：

1. 进入扫描页：确认右上角出现三个按钮，水平一行、右对齐，位于实时画面之上而非旁边/下方。
2. 明亮取景场景下确认按钮文字与边界仍清晰（验证半透明底板生效）。
3. 点悬浮 Torch：闪光灯开；再点：关。与底部 Torch 行为一致。
4. 点悬浮 Camera：前后摄像头切换可见。与底部 Camera 行为一致。
5. 点悬浮 Cancel：扫描页关闭回到主页。与底部 Cancel 行为一致。
6. 确认底部三个按钮仍然存在且可用。
7. 确认品红探针按钮已完全消失（包括点击后变色的测试行为与 Toast）。
8. 退出扫描页再次进入：右上角仍只有一组按钮（幂等性），相机预览仍为实时画面（未被破坏）。
9. 扫码成功：进入结果页后悬浮按钮不干扰结果内容；点 "Scan Again" 返回后悬浮按钮重新可见。
10. 桌面端启动：无悬浮按钮、无异常/崩溃。

**Prior art**：`docs/maui-overlay-verification.md` 中既有的"构建 → 模拟器运行 → 截图取证 → 记录结论"流程与记录格式；本次验证结果追加到同一文档。

## Out of Scope

- 移除或改造底部命令栏（本次是"新增第二组入口"，底部原样保留）。
- 悬浮按钮的自动隐藏/重现逻辑（如"仅在若干秒无操作后淡出"），以及另一个并行分支中出现过的 `ShowButtons` 状态机制。
- 按钮的激活态/开关态视觉同步（如闪光灯开启时按钮高亮），包括两组之间的状态联动。
- 结果页（Scan Again / 扫描结果卡片）的改造。
- 桌面端的悬浮按钮方案（含桌面端原生宿主注册、桌面端替代叠加实现）。
- Android 返回键处理、权限流程改造、扫描性能优化。
- 另一个并行分支中对比的 Avalonia 叠加与 Android Native 叠加两种替代方案（本次不引入）。
- 对扫描识别本身（识别率、识别速度、跳转逻辑）的任何改动。

## Further Notes

- **并行分支**：仓库中存在分支 `feature/three-scanner-variants`，它已实现"三个按钮悬浮在相机预览之上"的三套方案（Avalonia / MAUI / Native）并附有 spec 与 ADR。可参照其按钮面板的构建与摆放写法，但其按钮位置是**画面底部中央**，与本 spec 要求的**右上角**不同；且该分支不含本次基于的 SPIKE 改动，两边是并行实验路线，不要直接合并。
- **未决问题（沿用既有记录）**：`docs/maui-overlay-verification.md` 中挂记的"桌面端是否要保持可用"问题本次仍未解决——本 spec 选择接受桌面端不显示悬浮按钮，桌面端可用性另行处理。
- **实现前置**：本 spec 中的叠加机制依赖当前分支上由 SPIKE 提交引入的相机内容构建路径。实现时应在此基础上把探针替换为真实按钮组，而不是另起一条叠加实现。
- **中英术语**：代码与文档中既有英文标识（Torch / Cancel / Camera / ScannerView 等）保持原样，本 spec 的中文表述以 `CONTEXT.md` 中的术语为准。
